# 团队角色

[English](roles.md) | 中文

本页记录一支研究团队在这套 bundle 之上如何编成：有哪些角色、哪些是耐久成员、哪些是一轮即弃的子代理，以及每个角色可以做什么、不许做什么。[README.md](README.zh.md) 负责已实现的协作契约；本页是建立在它之上的用法契约，不是新机制。

## 两种角色

一个角色的工作跨轮、且别的成员需要能叫到它时，它是**耐久**的。耐久角色就是 Team Member：账本记着它、它有 Session、它出现在 Team 面板里、`@handle` 能叫到它。

一个角色只在一轮里为一件事存在时，它是**临时**的——比如为某一个 prover 写一份简报，或把一轮的草稿并排读一遍。临时角色是子代理：拥有它的角色把它起出来，拿回一个结果，它就没了。

本页还有第三样东西，它不是角色。尝试的 record 与已核验的 ledger 是 bundle 已经提供的机制，没有任何成员拥有它们。

## 名册

| 角色 | 它负责 | 形态 |
| --- | --- | --- |
| `orchestrator` | 把工作分到各方向、分配尝试名额、收判决、写 record 与 ledger | 耐久 |
| `prover` | 一条方向及其规格；不写实现 | 耐久 |
| `implementer` | 把规格落成可跑的实验；不解读自己的结果 | 耐久 |
| `verifier` | 对一件产物的独立复核：自己的实现、自己的数字 | 耐久 |
| `protocol-owner` | 判据本身：编号、单位、分母、可比性 | 耐久 |
| `advisor` | 跨轮日志趋势，以及下一轮的指令与名额分配 | 耐久 |
| `summarizer` | 从历史里读出某一个 prover 的简报 | 临时 |
| `crosscheck` | 把一轮的候选并排读，找共同盲点 | 临时 |
| `redteam` | 攻击录取判据本身 | 临时 |
| `auditor` | 从被拒的工作里打捞，以及死胡同的记录 | 临时 |
| `literature` | 相关工作，以及某条方向需要的定义 | 临时 |
| `comparator` | 在已核验的候选里挑最强的那份 | 临时 |
| `writer` | 把录取的结果扩写成自足文档 | 临时 |
| `finalaudit` | 成稿对照已录取的结果 | 临时 |

## 耐久角色不许做什么

这些禁令正是拆分值得存在的原因，所以它们属于角色的定义，而不属于它的提示词。

- `orchestrator` 与 `advisor` **对内容不持意见**。它们不得说哪条方向看起来有希望、不得推荐技术、不得宣布某条方向已死。它们的权限在过程上，不在内容上。
- `implementer` **不解读自己的产出**。它报告跑了什么、产出了什么、以及与规格的每一处偏离，到此为止。
- `prover` **不写实现**。一条不写代码就说不清的方向，还不是一条方向。
- `verifier` **不复用作者的实现**。一次 import 了被测代码的复核，会把作者的错误连同作者的数一起复现出来。

## 交接

规格从 `prover` 传到 `implementer`，回执从反方向回来。两者都是普通的 Thread 消息；形状固定，是为了让偏离**可见**，而不是让人去猜。

规格写明：一句话的问题；按编号、单位、分母给出的判据；对照臂；种子数与折数；预期效应量；以及出现什么结果就判这条方向死。

回执写明：脚本路径、环境、墙钟耗时、实际使用的种子，以及**与规格的每一处偏离，逐条列出**。悄悄换掉单位或分母，正是这个形状存在要防的那种失败。

两条消息都不携带结论。结论是 `verifier` 与这一轮的事。

## 录取

- 一个候选只有在逐件复核**与**并排复核都通过时才算录取。一次复核不是判决。
- 每一次复核都是对抗式的：每一步在被证明之前都是错的，每一条引用在被读过之前都是可疑的。
- spawn 权属于拥有临时角色的那些角色。`prover` 不起 `summarizer`，`orchestrator` 起。
- 这份权限是 **preset 决定的、不是靠人记的**：`orchestrator` preset 挂了 delegation 行，其余 Member preset 都没挂。
- 所以挂在 `team-member` 上的成员手里根本没有起子代理的工具；至少要有一个成员以 `orchestrator` 身份入队，否则上表里任何临时角色都不存在。

## 现状

上表是目标。bundle 今天提供的东西与它有两处差别，这些差别写在这里，而不是留给人去猜。

加成员在设计上就是人类操作：负责加成员的 Remote 把执行者记为人类，所以任何成员都造不出另一个成员。因此耐久角色只能手工创建；而临时角色根本不是成员。

耐久角色里有三个还没有机制托底。没有东西写按 prover 定制的简报，没有东西跨轮读验证日志，也没有东西从被拒的工作里打捞已核验片段、或记下死胡同。
